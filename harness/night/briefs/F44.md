- TEL-01: `AnalyticsRepository` and `CrashReporter` protocols with Firebase implementations. Staging and Prod use separate Firebase projects; Dev sends nothing.
  - Configure Firebase at launch with `FirebaseOptions(googleAppID:gcmSenderID:)` plus `apiKey` and `projectID` from those Info.plist keys, ONLY when all four are non-empty and the environment isn't dev.
  - Otherwise use no-op implementations and never touch Firebase. Never call `FirebaseApp.configure()` without options: it crashes without a GoogleService-Info.plist.
  - Test the decision.
- TEL-02: consent is two independent toggles, both on by default, re-applied at launch: analytics collection enabled, and Crashlytics collection enabled. Identity is the Supabase user UUID only.
- TEL-03: the non-Got-This, non-reminder events, with params limited to enums, buckets and ids, never item names, emails or codes. The full list is in PARITY TEL-03. This task builds the mapper and the events. Calling them from the view models is F45 (later); don't edit the features.
- TEL-05: no App Tracking Transparency prompt and no IDFA.
- ERR-03: only Unknown and Database errors are reported to Crashlytics as non-fatals, from safeCall. Hook the reporter into `SafeCall` through the existing `AppErrorReporter` seam, and keep the current SafeCall tests passing.
- Tests must not hit the network or touch Firebase: everything goes behind the protocols with fakes.
