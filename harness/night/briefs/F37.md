## Notes
- Test class: `ProfileViewModelTests` (at least 27, in `BabeGetThisTests/Profile/`).
- PROF-01, the profile sheet, opened from the avatar:
  - It shows only while an account exists, and closes on sign-out. The close-on-sign-out part is already done in `ListsViewModel`.
  - A large avatar: the name's initial, or a person icon.
  - A "Name" field with a trailing Save, shown only when the trimmed value is non-blank and has changed. Messages "Name cannot be empty" / "Name updated".
  - The email, read-only, or "No email".
- PROF-02, log out:
  - Push first. If changes are still unsynced, ask "Sign out?" with "Sign out anyway" / "Cancel".
  - Then evict the account lists, sign out and reset Welcome.
- PROF-03, delete account:
  - Confirm "Delete account?" with the deletion body, and "Delete" / "Cancel".
  - Order: push → RPC `delete_user` → evict → reset Welcome → "Your account has been deleted".
  - A failure keeps every list on the phone.
- NAV-04: sign-out and account deletion clear the stack to Welcome. A lost session (SessionExpired) stays put.
- Data sources, all existing; don't re-implement them:
  - `SyncEngine.push()`, `hasUnsyncedChanges` and `evictAccountLists(andThen:)` (F26, F29) via `container.syncEngine` (lazy).
  - `AuthRepository.updateUserName`, `logout` and `deleteAccount` via the container's auth repository.
  - `WelcomeRepository`, to reset Welcome.
  - Put them behind small protocols in `Features/Profile/` so the view model is unit-testable.
- Eviction and sign-out order matter: the lists are evicted BEFORE the session is destroyed (`evictAccountLists(andThen:)` runs the sign-out). For deletion, eviction happens only after the account is gone.
- Strings: no String Catalog yet. Use SwiftUI literals with Android's exact wording.
- Colours via `AppColors`, spacing via `AppMetrics`.
- F42 (Settings) runs in parallel and owns `Features/Settings/` only. Don't edit it.
