# Night 2026-11-12a — F01 (f01-errors)

## Summary
Ported Android's `AppError`, `SafeCall` and `NetworkMonitor` (feat/got-this) to Swift, test first. All three Android test classes were ported faithfully.

- `BabeGetThis/Core/Errors/AppError.swift` has `enum AppError` with the same cases and default copy as Android (`.database`, `.network`, `.server(code:message:)`, `.timeout`, `.validation`, `.notFound`, `.auth`, `.unauthorized`, `.unknown`). It is Equatable and a LocalizedError. It also has `AppErrorException`, which passes a deliberately chosen AppError straight through `safeCall`. Repositories return Swift's `Result<T, AppError>`, which stands in for Android's `Result`.
- `BabeGetThis/Core/Errors/SafeCall.swift` has `struct SafeCall`, called as `try await safeCall(onUnauthorized:onClientError:) { … }` and returning `Result<T, AppError>`.
  - Cancellation (`CancellationError`, or a `URLError(.cancelled)`) is rethrown as a typed `throws(CancellationError)`. It is never mapped or reported.
  - It runs on the caller's isolation (`#isolation`), so non-Sendable blocks are fine under Swift 6.
  - Mapping, from Android type to iOS equivalent:
    - SQLiteException → GRDB `DatabaseError`
    - UnknownHost / Connect / SSL / SocketTimeout → `URLError` codes (same copy)
    - Retrofit HttpException → the new `HTTPStatusFailure`
    - Supabase RestException → `AuthError.api` (status from `underlyingResponse`) and `FunctionsError.httpError`
    - Supabase transport failures and timeouts → raw `URLError`, because supabase-swift rethrows these unwrapped
  - Anything unrecognised becomes `.unknown()`. Its text is logged with `.private` privacy and never surfaced.
- `BabeGetThis/Core/Errors/AppErrorReporter.swift` has the `AppErrorReporter` protocol (non-throwing) and `SilentAppErrorReporter`.
- `BabeGetThis/Core/Network/NetworkMonitor.swift`: `NetworkMonitor.isOnline()` reads a `NetworkPathSource` every time, with no caching. Online means `status == .satisfied` (iOS's equivalent of INTERNET+VALIDATED). `.requiresConnection` (captive portal), `.unsatisfied` and "no path yet" all count as offline. `SystemNetworkPathSource` wraps `NWPathMonitor` behind the protocol, and tests use a fake source.
- `BabeGetThis/Core/Network/HTTPStatusFailure.swift` is the status error our own URLSession clients throw. Its status line ("HTTP 600") is passed through only for out-of-range codes, as on Android.

Tests:
- `AppErrorTests`: 7, all ported.
- `SafeCallTests`: 26. That is the 23 ported tests plus three iOS checks: cancellation is rethrown and not reported, a mapped error reaches the reporter, and an `AppErrorException` passes through.
- `NetworkMonitorTests`: 7. That is the 6 ported (an expensive/constrained path stands in for Android's "validated but no INTERNET" combination, which iOS can't express) plus one check that the real `NWPathMonitor` source can be created and read.
